# What تلفزيونك already does: look here before you build anything

The same features explained for people, in Arabic: [FEATURES.md](FEATURES.md).

For an agent working on a TV that has تلفزيونك, during the setup or any time after. When the person asks for
something about the screensaver, the home screen or the TV, find it in the tables below and run its command.

## Rules

- **Use the setting.** Everything below is already in the apps; one command changes it, the screen redraws, and
  it stays through every update.
- **Never build or patch the apps for a request.** No editing `android/`, `src/` or `dist/`, no building an APK,
  no installing your own build, no turning the automatic update off. The next update would undo it, a build of
  your own can't update itself afterwards, and the TV is left on a version nobody else has.
- **Not in the tables?** Tell the person, in Arabic, that it isn't in تلفزيونك yet, and that their words can go
  to the developer as a suggestion: add them to the share message at the end (`optimize/share.sh --preview
  --owner "<their words>" …`, see `docs/SETUP-PROMPT.md` step 8). Don't make it yourself.
- **A problem goes to the developer's form, never to GitHub.** When something doesn't work, or the person says «بلّغ المطوّر
  عن مشكلة» (now or any time later, from this computer or another one): look into it first with the tools here,
  then `optimize/share.sh --preview --problem --agent "<you and your model>" --owner "<their words>" "<what you checked
  and found, two to five plain lines>"`, show the person the whole text, ask «أرسله؟», and only if the person says yes
  `optimize/share.sh --send`. Never open a GitHub issue, discussion, comment or pull request for the person, never use `gh`
  or the GitHub website on their behalf: the developer reads the form, and a GitHub post is public and can carry their
  details. If the TV doesn't answer, send it anyway: the report says so.
- **Close to one?** Offer the nearest setting (a trip date: the countdown; a darker card: `cardstyle dark1`).
- **After a change:** read it back (`optimize/saver.sh show`, `optimize/dock.sh show`) and look at a screenshot
  (`optimize/shot.sh screensaver` or `optimize/shot.sh home`, the `-small.png`) before you say it's done.
- `optimize/saver.sh`, `optimize/dock.sh` and `optimize/music.sh` with no arguments list every option.
  Names and texts go in single quotes; no apostrophes inside them.

The settings screen (for telling the person where a row is) opens on eight category tiles, two to a row from the right, each with
its current value: «الموقع والصلاة», «الأذان», «شاشة التوقف», «الشاشة الرئيسية», «المباريات والأسواق», «التطبيقات والمفضلة»,
«العائلة», «الجوال والتحديث». OK opens one, Back returns to its tile. Which row is in which tile: `SettingsHub.ROWS` in the
screensaver app, and the list in docs/FEATURES.md. «تحديث تلفزيوني» is in «الجوال والتحديث». The commands below are unchanged.

The home screen's own helpers are refused (`optimize/restore.sh` is for those) |
| TCL: the adhan alarms or the sleep timer stop after a restart | `optimize/autostart.sh` (allows auto-start for our two apps on a TCL and writes it to disk; `autostart.sh check` reads it; the setup does it already) |
| the person turned debugging off on the TV, is it really closed? | `optimize/find-tv.sh --closed` (`OK: ADB is closed`, `!! ADB still answers …` or `?? Can't tell` when the TV sleeps). The apps' data and content update without ADB; a new version of the apps and any change of settings from the computer need it, so it is turned on again then |
| a TV system update brought the old home back, or apps back on | `optimize/run.sh again` (settings stay) |
| what the speed tweaks changed, and putting exactly that back | `optimize/tweaks.sh status` (each setting, and the Play Store's standby bucket and background appops: was, now), `optimize/tweaks.sh restore` (once: the journal is then kept as `tweaks-journal.done` and a second restore does nothing; the values recorded before the first apply in `optimize/run/tweaks-journal.txt`; a value that was not set is deleted; a TV that refuses one gets a `!!` line). `optimize/measure.sh` lists the tweaks beside each reading, and the report shows the same (before and after) |
| restore scripts that need only adb | `optimize/backup.sh scripts`: writes `optimize/run/restore-scripts/restore.sh` and `restore.bat`, one `adb shell` command per line with exact quoted values, from the home switch journal, `backup.txt`, the tweaks journal and the family DNS journal (home, apps the setup turned off, tweaks, the TV's own screensaver, Private DNS). A value with a character they do not send is left out with a `!!` line. No addresses, serials or names in them |
| «حماية العائلة (DNS)»: Private DNS to AdGuard Family (off by default; Android 9+; needs the home app) | `optimize/dock.sh familydns on|off|status|grant`. The home app (a version with this feature; run `optimize/install.sh launcher` first, else a plain line says so and nothing changes) does the work on the TV, so a dropped connection cannot leave it half switched, and keeps the one record. `on` checks the TV can reach `family.adguard-dns.com` on port 853 (a `!!` line and nothing changed if not), records what the TV had, sets it, then waits until the system takes it and a fresh name resolves and the internet answers through it (a `!!` line and the old values back if not). `on` also gives the app its permission (`WRITE_SECURE_SETTINGS`) when it is missing; `grant` does only that (recorded in `grants-journal.txt`, taken back by `reset.sh`). `off` puts back exactly the recorded values (a value that was not set is deleted; a setting someone else changed since is left alone). The automatic revert is only for that first check; afterwards use `off` or the TV row (الإعدادات ← الشاشة الرئيسية ← حماية العائلة). `reset.sh` stops, before it removes anything, if the original cannot be put back; on a TV whose home app has no such feature it just goes on |
| which TV is mine, when several devices answer | `optimize/find-tv.sh` lists every device with ADB open (address, brand, model, Cast name) and does not pick when there is more than one; the person says which is the TV and the agent runs `optimize/find-tv.sh use <IP>` |
