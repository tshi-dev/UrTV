# UrTV against three open-source TV projects (2026-11-18)

Text only. Nothing of their code or screenshots is in this repository; where an idea is worth taking, the entry says where it would go in
ours and what it would cost in licence terms. Ours = branch `work/45-compare` (same tree as `work/44-review`, VERSION 4.4).
Their side is the shallow clone of each default branch on 2026-11-18; each clone holds one squashed commit, so there is no history to read.
File:line on their side is relative to the repo root of the project named in the row. Lines marked `~` are approximate.

**Name choice.** "CleanYourTV" is unambiguous (the 59k-star repo; the others found are forks or derivatives: tvhome-zh, vgs-cleantv, TiviKit,
cleanyourtv-app). "couch-tv" matched several repos; I took Seagey/couch-tv because it is the one with an Android TV home screen and
debloat tooling (the others are a Tizen streaming app and a Samsung hub). "tvOS Launcher" has many look-alikes (aerial-tv 12k stars, Tigris, luma-tv, glass-tv-home);
I took `techgenius1/tvOS-Launcher` because it is the repo literally named that, is Apache-2.0 and ships Android TV launcher code. If the intended one was aerial-tv or Tigris, say so and this needs a second pass.

**What did not hold up when I read the code instead of the README**
- tvOS Launcher "one-tap local ADB" is not one tap: it can flip ADB on by itself only if it already holds WRITE_SECURE_SETTINGS; on a fresh TV the person enables network debugging first (`src/com/techgenius/tvoslauncher/LocalAdb.java:128-205`). Its `qrcodegen` is not used for ADB, only for an admin URL and sign-in popups.
- tvOS Launcher "Home Button Fix" comment says "off by default", the code defaults it to true (`ButtonMapper.java:206-207`).
- tvOS Launcher "Liquid Glass" is not RenderEffect (the import in `MainActivity.java:33` is unused).
- couch-tv "Home button works" is a bounce-back, not default-launcher ownership: the stock home flashes first (`tv-home/android/.../FireWatch.kt:1-110`, README admits it for Fire TV).
- couch-tv "debloat" is one package by default (`apply.sh:80-83`) plus 24 opt-in; it is not a debloater in the CYT sense. Its "safety ratings" are only source attributions (`tv-home/tools/privacy-list.txt:3-25`).
- CYT "glass" is a moving sheen, not frosted glass (`GlassView.java`); there is no blur code in its launcher.
- A first count of CYT's unique packages (5,487) was wrong; a recount with the same script on both trees gives 1,828 (CYT, 489 lists, 11,044 lines) against 1,707 (ours, 416 lists, 9,584 lines). We are 73 lists (15%) behind.

## 8. We do better (keep as is)

- First-frame discipline, and the rule that the UI thread never queries across processes, enforced by a static test (R-001). CYT's UI-thread icon loads and tvOS's reload-everything-per-change are the failures it prevents.
- Two real safety nets for a bad home: safe mode on a plain screen with the TV's own home one press away, plus a rescue app and BootGuard auto-restore. Theirs stop at "open the stock home".
- Debloat that runs on the TV itself and fails closed (an unreadable answer means nothing is turned off), with the same input guard in the computer script and the on-TV engine, kept equal by a test.
- A ledger written before the batch and confirmed afterwards, never touching what the TV already had off; several independent ways back.
- A Home key catch instead of a bounce-back, and a measured per-model HomeDoctor.
- Pre-blurred glass shared between two apps, no live blur, per-photo contrast guarantee.
- Arabic-first RTL; the other RTL work I looked at is Hebrew-first or Latin-font-only.
- The regression table: 273 rows, each with symptom, cause, version and a guard test, indexed by a test that fails on a row without one.
- A generated and tested settings reference; reports sent only after a preview; updates only over the signed release channel.

## 9. Don't adopt (and why)

- **Build-it-yourself release model** (CYT builds on the person's computer and signs with the debug key; couch falls back to the debug key). AGENTS.md: a self-built APK can never update. Opposite of our rule.
- **GuardRevival (a NotificationListenerService kept alive to be rebound after a force-stop) and `ServiceRepair`** (CYT). Another special grant and another service Play Protect can look at, after we removed the home's accessibility service in 4.3.3 for exactly that reason. Revisit only if HomeDoctor shows a TV that force-stops our home and does not restart it.
- **Add-on app contract and themes** (CYT). 38 external apps and 112 config entries are a large support surface. Our one add-on plus scene packs is enough.
- **WebView as the whole UI** (couch). 145-209 MB on a 2.4 GB TV by its own measurement.
- **tvOS Launcher's accessibility-overlay panels, button mapper, hidden-API grants, key-swallowing multi-tap, always-on keep-alive and getevent streaming.** Broad permissions, swallowed keys and constant background work on a 1-1.5 GB TV. Its `hidden_api_policy` change is global and persistent.
- **tvOS's "EOF during install-commit counts as success"** (`LocalAdb.java:1414-1418`): it can hide a real failure. Ours reads the state back.
- **couch's privacy list as a debloater** (24 packages, source attribution as "safety"). Ours is already stricter and larger.
- **RenderEffect or window blur-behind.** SDK 31+ only; our TVs are mostly older.
- **Bundling fonts or logos without a licence** (tvOS ships Bahnschrift, a Microsoft font, plus Antonio, VarelaRound and brand logos with no entry in its NOTICE, `src/Ui.java:48-50`; couch has no NOTICE for its OFL and CC-SA material). A reminder to keep our own `THIRD_PARTY_NOTICES.md` and `docs/LICENSE-CONTENT.md` as they are.
- **Undo state only on the computer** (couch). Ours keeps a copy on the TV.
